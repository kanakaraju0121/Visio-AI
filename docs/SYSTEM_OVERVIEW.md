# System overview

## High-level architecture

```text
                    ┌──────────────────────────┐
                    │       User speech        │
                    └────────────┬─────────────┘
                                 │ microphone
                                 ▼
                    ┌──────────────────────────┐
                    │ SpeechRecognition        │
                    │ Google speech service    │
                    └────────────┬─────────────┘
                                 │ recognized text
                                 ▼
                    ┌──────────────────────────┐
                    │ Command routing          │
                    │ sr_mic_test.py           │
                    └───┬───────────┬──────────┘
                        │           │
              motor cmds │           │ camera / AI cmds
                        ▼           ▼
             ┌────────────────┐  ┌───────────────────────┐
             │ motor_control  │  │ camera + YOLO stream  │
             │ RPi.GPIO/L298N │  │ Picamera2/OpenCV      │
             └───────┬────────┘  └──────────┬────────────┘
                     │                     │
                     ▼                     ▼
               DC gear motors        browser MJPEG stream

                      Other question text
                               │
                               ▼
                    ┌──────────────────────────┐
                    │ Optional Groq API        │
                    │ visio_ai/ai.py           │
                    └────────────┬─────────────┘
                                 │
                                 ▼
                           espeak / aplay
```

## Main runtime sequence

1. `visio_ai_project/sr_mic_test.py` initializes speech recognition and the L298N motor driver.
2. The microphone captures a phrase. The current implementation calls `recognize_google`, so recognition needs internet access.
3. The recognized phrase is routed to a motion command, camera/stream action, photo capture or optional Groq response.
4. Spoken feedback is generated by `visio_ai_project/visio_ai/audio.py` using `espeak` and `aplay`.
5. The stream manager starts `yolo_stream_server.py` as a child process and writes its output to `data/logs/yolo_stream.log`.

## Main modules

| Module | Responsibility |
|---|---|
| `sr_mic_test.py` | Voice input and command routing |
| `motor_control.py` | PWM and direction signals for two L298N channels |
| `camera_access.py` | Still-image capture using PiCamera2 or OpenCV |
| `object_detection_yolo.py` | Local YOLO preview and detection reporting |
| `yolo_stream_server.py` | MJPEG browser stream with YOLO annotation |
| `register_face.py` | Experimental enrollment of face image features |
| `video_stream_server.py` | Camera stream with experimental face matching and enrollment endpoint |
| `visio_ai/ai.py` | Optional cloud-based conversational response |
| `visio_ai/audio.py` | Text-to-speech output |
| `visio_ai/stream.py` | Child-process lifecycle for the YOLO server |

## Data and configuration

- Configuration is provided through environment variables. Copy `.env.example` to `.env` and export the values before starting the application.
- Runtime files are stored under `data/` and excluded from Git.
- Model weights are downloaded or supplied locally; large binary model files are not part of the source repository.
- TLS certificate and private key files are generated locally and must remain untracked.
